# Architecture Decisions and ADR Register

The Sprint 1 Definition of Done discussed an initial architecture, at least two Architecture Decision Records (ADRs), a data model, and a reproducible seed. The register below distinguishes confirmed project constraints from decisions that still require a signed-off ADR.

## ADR template

Each accepted ADR should include:

- **Status:** Proposed, Accepted, Deprecated, or Superseded.
- **Context:** the problem and constraints.
- **Decision:** the selected option, written unambiguously.
- **Alternatives considered:** include the reasons for rejection.
- **Consequences:** operational, cost, reliability, and maintenance impacts.
- **Traceability:** related RN/F/HU/US IDs.

Do not mark a proposed decision as Accepted until the team has reviewed it.
