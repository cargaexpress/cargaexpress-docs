# Sprint 2 — User Stories and Subtasks

Sprint 2 focused on building the carrier integration layer and the core API. The work is organized into two weeks with distinct objectives.

## Week 1: Data model, state mapping, and order endpoints

**Observed dates:** 29 September to 5 October 2026

| Story | Jira | Title | Epic | Status |
|---|---|---|---|---|
| HU-11 | RIWI-52 | Implement the Complete WMS ORM Model | Data Model & Persistence | Merged to `main` |
| HU-12 | RIWI-57 | Create the Configurable State Mapping Model | Data Model & Persistence | Merged to `main` |
| HU-13 | RIWI-63 | Order CRUD Endpoints | Core Endpoints | Merged to `main` |

### HU-11 — Implement the Complete WMS ORM Model

**Goal:** Create the SQLAlchemy models and initial Alembic migration for the 12 operational tables.

| Subtask | Jira | Work |
|---|---|---|
| Create Order model | RIWI-53 | `brand_id`, `dc_id`, `created_at`, `dispatched_at`, `status` |
| Create Shipping Label model | RIWI-54 | 1 order → N shipping labels (RN-07) |
| Create Carrier Event model | RIWI-55 | Raw status + canonical status + timestamp |
| Generate and apply initial migration | RIWI-56 | Alembic `upgrade head` |

### HU-12 — Configurable State Mapping

**Goal:** Translate each carrier's status into canonical states, with mapping changeable without restart (CA-06).

| Subtask | Jira | Work |
|---|---|---|
| `StateMapping` model | RIWI-58 | `carrier_id`, `raw_status`, `canonical_status` |
| Initial seed for simulated carriers | RIWI-59 | ≥6 distinct source statuses per carrier |
| In-memory cache with invalidation | RIWI-60 | 300s TTL, invalidated on write |

**Result:** `state_mapping` table with `UNIQUE(carrier_id, raw_status)` and `CHECK` constraint on canonical status. Admin API at `/api/v1/admin/state-mappings`. Migrations `a3f1c9d27b45`, `b7e24d51c8a9`, `c4a1209b7e6f`.

### HU-13 — Order CRUD Endpoints

**Goal:** Expose the basic order life cycle through the API.

| Subtask | Jira | Work |
|---|---|---|
| `POST /api/v1/orders` | RIWI-64 | Create order with lines and recipient |
| `GET /api/v1/orders` and `GET /api/v1/orders/{id}` | RIWI-65 | Paginated listing and detail |
| `PATCH /api/v1/orders/{id}/status` | RIWI-66 | Status update (direct, RN-02 not yet enforced) |
| pytest tests | RIWI-67 | Integration tests against real PostgreSQL |

:::warning
Jira names the update `PATCH /orders/{id}/dispatch`, but the code serves `PATCH /orders/{id}/status`. The update is direct: RN-02 (terminal state protection) is not implemented yet.
:::

### HU-17 — Webhook Simulator (5 Type A Carriers)

| Subtask | Jira | Work |
|---|---|---|
| Random event generator per carrier | RIWI-83 | Lifecycle-based generation with weights |
| Catalog of ≥6 statuses per carrier | RIWI-84 | 10–11 statuses each, covering all 8 canonical |

### HU-19 — Type C File Simulator

Three carriers generating CSV/XLSX files with configurable defect injection. Includes WMS seeder.

### HU-23 — RabbitMQ Queue

A `rabbitmq` service with management interface, persistent storage, and credentials from `.env`. AMQP port `5672`, web interface `15672`. Not yet merged into `main`.
