# Type B API Simulator (Pull / REST APIs)

The Type B simulator supports testing pull-style carrier integrations (Requirement **F4**). The documented contract queries shipments individually by tracking number and supports configurable throttling, status catalogs, and failure scenarios.

---

## Architecture & Live Endpoints

The Type B ecosystem runs as 4 independent microservices with polyglot database backends, unified behind an Nginx Reverse Proxy Gateway with automated Let's Encrypt SSL certificates.

| Carrier Service | Database Engine | Local TCP Port | Live HTTPS Gateway Endpoint |
|---|---|:---:|---|
| **Carrier A** | PostgreSQL 16 | `8001` | [`https://cargaexpress-simulator-b.mooo.com/carrier-a/docs`](https://cargaexpress-simulator-b.mooo.com/carrier-a/docs) |
| **Carrier B** | MySQL 8.4 | `8002` | [`https://cargaexpress-simulator-b.mooo.com/carrier-b/docs`](https://cargaexpress-simulator-b.mooo.com/carrier-b/docs) |
| **Carrier C** | MongoDB 7.0 | `8003` | [`https://cargaexpress-simulator-b.mooo.com/carrier-c/docs`](https://cargaexpress-simulator-b.mooo.com/carrier-c/docs) |
| **Carrier D** | SQLite 3 | `8004` | [`https://cargaexpress-simulator-b.mooo.com/carrier-d/docs`](https://cargaexpress-simulator-b.mooo.com/carrier-d/docs) |
| **Unified Gateway** | Nginx (Alpine) | `80`, `443` | [`https://cargaexpress-simulator-b.mooo.com/`](https://cargaexpress-simulator-b.mooo.com/) |

## API Contract & Endpoints

Each carrier exposes standard endpoints conforming to the Type B polling specification:

### 1. Query Shipment by Tracking Number
```http
GET https://cargaexpress-simulator-b.mooo.com/{carrier_prefix}/shipments/{tracking_number}
```
*Example:*
```bash
curl -s https://cargaexpress-simulator-b.mooo.com/carrier-a/shipments/TRK-A-000001
```

### 2. List All Shipments
```http
GET https://cargaexpress-simulator-b.mooo.com/{carrier_prefix}/shipments?limit=50
```

### 3. List Tracking Events
```http
GET https://cargaexpress-simulator-b.mooo.com/{carrier_prefix}/events?limit=50
```

### 4. Healthcheck
```http
GET https://cargaexpress-simulator-b.mooo.com/{carrier_prefix}/health
```

## Throttling and Failure Scenarios

- **Rate Limiting**: Configurable per carrier (default: 60 requests/minute). Requests exceeding the quota return HTTP 429 (`Too Many Requests`).
- **Simulated Scenarios**:
  - `?scenario=server_error`: Simulates internal carrier outage (HTTP 500).
  - `?scenario=unavailable`: Simulates transient maintenance (HTTP 503).
  - `?scenario=not_found`: Simulates unregistered tracking number (HTTP 404).

---

## Database Architecture & Storage Resolution

The Type B implementation successfully resolved the polyglot storage model:
1. **Carrier A**: PostgreSQL with relational tables (`shipments`, `events`).
2. **Carrier B**: MySQL with structured tracking tables.
3. **Carrier C**: MongoDB document store with nested event arrays.
4. **Carrier D**: Embedded SQLite for lightweight offline operation.

The seed process initializes the dataset deterministically (`SEED=42`), while the periodic generator continuously injects events into all 4 databases.
