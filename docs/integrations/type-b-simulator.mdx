# Type B API Simulator (Pull)

The Type B simulator supports testing a pull-style carrier integration. The documented contract queries a shipment individually by tracking number and supports configurable throttling and failure scenarios.

## API contract

```http
GET /shipments/{tracking_number}
```

Example shape:

```http
GET /shipments/RX-83921
```

The endpoint returns the simulated shipment record for the supplied tracking number, subject to the simulator's configured response and error behavior.

## Requirements discussed for the simulator

- Query by tracking number.
- Support configurable rate limiting; the integration requirement discusses a 30-minute polling/limit interval. Confirm the exact semantics against the approved contract.
- Support explicit error scenarios so consumers can test recovery behavior.
- Provide four simulated carrier APIs with carrier-specific status catalogs (at least six statuses per carrier).
- Use different date formats across carriers and include out-of-order events to test normalization and event-order handling.
- Keep seed data versioned, deterministic, and idempotent.

## Local test examples reported during development

These examples were shared in the project conversation. Verify that the port-to-service mapping matches the current simulator repository before using them as a test runbook.

| Local URL example | Scenario |
|---|---|

| `http://localhost:8003/shipments/PK-3001?scenario=not_found` | Not found |
| `http://localhost:8004/shipments/NO-EXISTE` | Unknown tracking number example |

## Storage decision needs reconciliation

A later project description referred to four independent services using PostgreSQL, MySQL, MongoDB, and SQLite respectively. An earlier HU-18 decision discussion preferred minimizing infrastructure and reusing PostgreSQL if viable. These statements should be reconciled against the actual code and an accepted ADR; this page does not silently choose one as the final architecture.

## What this simulator does not prove

The simulator can provide test responses, but it does not by itself prove that the Control Tower's ingestion pipeline, canonicalization, transition rules, persistence, SLA calculations, or user-facing visibility are complete.
