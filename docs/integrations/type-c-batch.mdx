# Type C Batch File Simulator

Standalone module and autonomous microservice for generating synthetic tracking and status files for Type C batch carriers with configurable defect injection, plus idempotent database seeding for WMS integration.

> Fulfills **Requirement F5 — Type C carrier files** (user story **HU-19**, RIWI-88): CSV/Excel files deposited every 4 hours into S3-compatible Object Storage (MinIO) with automated retention cleanup.

## Defect Injection Engine

The simulator automatically injects controlled data quality defects during each cycle to test the ingestion pipeline's resilience:

| Defect Type | Description |
|---|---|
| **Header Corruption** | Noise or repeated header lines inserted mid-file |
| **Missing Columns** | Mandatory tracking and status columns omitted or null |
| **Unmapped Status Codes** | Unknown codes not present in the official catalog |
| **Trailing Totals** | Summary lines (`TOTAL,100,OK`) appended after data rows |
| **Nonexistent Waybills** | Injected fake waybills (`FAKE_WAYBILL_XXXXXX`) not present in WMS |
| **Mixed Timestamps** | ISO 8601 timestamps mixed with `DD/MM/YYYY HH:mm` formats |

## MinIO Object Storage Architecture (F5)

Batch tracking files are autonomously deposited into an S3-compatible **MinIO** storage engine (`pgsty/silo:latest`):

- **Deposition Frequency**: Every 4 hours (`INTERVAL_HOURS=4`).
- **S3 Bucket**: `type-c-carriers`.
- **Partitioning Layout**:
  - `carrier_{id}/{YYYY-MM-DD}/carrier_{id}_events_{timestamp}.{csv|xlsx}`
  - Pointer for instant extraction: `carrier_{id}/latest.{csv|xlsx}`
  - Manifests: `manifests/cycle-{timestamp}.json` and `manifests/latest.json`
- **Zero-Cost Retention Policy**: Automated retention cleanup purges files older than `RETENTION_DAYS=3` during each cycle to eliminate storage bloat and cloud fees.

## Docker & Deployment Architecture

```yaml
# compose.yaml
services:
  minio:
    image: pgsty/silo:latest
    ports: ["9000:9000", "9001:9001"]
    volumes: [minio_data:/data]

  type_c_simulator:
    build: .
    ports:
      - "8005:8005"   # Carrier 1 API
      - "8006:8006"   # Carrier 2 API
      - "8007:8007"   # Carrier 3 API
    environment:
      MINIO_ENDPOINT: http://minio:9000
      INTERVAL_HOURS: 4
      RETENTION_DAYS: 3
```

- **Container Footprint**: Multi-stage Alpine image (~54.5 MB), unprivileged non-root user (`appuser`, UID 1000).
- **CI/CD**: GitHub Actions workflow (`deploy.yml`) with automated `pytest` suite and SSH deployment to AWS EC2 using GitHub Secrets.
